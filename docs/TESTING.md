# Тестирование GOBLIT

## Автоматические проверки

Одна команда: `./tools/check.sh`.

| Шаг | Инструмент | Что проверяется |
|---|---|---|
| Форматирование | StyLua | единый стиль кода (`stylua.toml`) |
| Логика и данные | Lune, `tests/` | см. список ниже |
| Типы и линтер | luau-lsp + определения Roblox API | strict-типы во всём `src`, существование классов, свойств и методов Roblox, неиспользуемые переменные |
| Свойства интерфейса | `tools/check_ui_props.py` | имена свойств в `Ui.new / Ui.label / Ui.button`: туда они передаются таблицей, и тип-чекер их не видит |
| Линтер | selene | дополнительные правила; пропускается, если не удаётся скачать API Roblox |

Сборка места `rojo build -o GOBLIT.rbxlx` дополнительно проверяет структуру проекта и свойства в `default.project.json`.

### Что покрывают тесты Lune

- **Rng.** Совпадение с эталонной JS-реализацией Mulberry32. Детерминизм по seed, границы `nextInt` / `nextNumber`, ошибки на некорректный seed, нормализация seed. Независимость `fork` от уже взятых чисел. Веса (нулевые не выбираются, распределение пропорционально), `shuffle`, FNV-1a.
- **ProfileSchema.** Новый игрок, мусор вместо данных, миграция v0 → v1. Исправление отрицательных, NaN, дробных, огромных и строковых значений. Отбрасывание неизвестных и испорченных настроек. Флаг `newerVersion`, идемпотентность миграции, отсутствие общих ссылок с исходными таблицами, проверка значений настроек.
- **Данные.** `Config` глубоко заморожен, `Min ≤ Max` для всех пределов, базовые характеристики в пределах, соотношение автосохранения и TTL блокировки. Перки ссылаются только на существующие характеристики, редкости и категории. Параметры врагов корректны. У каждой категории комнат есть шаблон с 4 входами. Препятствия не выходят за стены и не перекрывают проходы. Точки появления не находятся внутри препятствий.

Тест данных комнат уже нашёл настоящую ошибку: в шаблоне «Круг колонн» враги появлялись бы внутри колонны.

Эталонные значения Mulberry32 получены так:

```js
function mulberry32(a){return function(){a|=0;a=a+0x6D2B79F5|0;let t=Math.imul(a^a>>>15,1|a);t=t+Math.imul(t^t>>>7,61|t)^t;return((t^t>>>14)>>>0)/4294967296}}
```

## Чего автоматические проверки не покрывают

Код, работающий с экземплярами Roblox (постройка мира, персонажи, DataStore, интерфейс в рантайме), нельзя выполнить вне Studio. Тип-чекер подтверждает, что API используется правильно, но не подтверждает **поведение**. Поведение проверяется вручную по плану ниже.

### Проверка защиты сетевых событий

В окне клиента (*Test → Clients and Servers*) выполните в командной строке:

```lua
local r = game.ReplicatedStorage.GoblitNet.UpdateSetting
for i = 1, 20 do r:FireServer("UiScale", 0.85) end   -- превышение частоты
r:FireServer("UiScale", 5)                           -- недопустимое значение
r:FireServer(string.rep("x", 100), true)             -- слишком длинный ключ
```

Ожидается: в Output сервера одно сообщение `[GOBLIT][Net] отклонён …` (последующие ограничены раз в 30 с), без ошибок скриптов. Настройка не принимает недопустимое значение.
