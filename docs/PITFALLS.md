# Ловушки GOBLIT

Журнал проблем, на которые мы наступили в этом проекте, и способов их обойти. Каждая новая находка записывается сюда сразу, вместе с датой.

Уроки прошлого проекта — в [LESSONS_BRAINROT_BANDITS.md](LESSONS_BRAINROT_BANDITS.md).

## Luau и проверка типов

**Строки во вложенных таблицах «расширяются» до `string`** (2026-10-19).
Если записать `{ kind = "chest" }` внутри большой таблицы данных, тип-чекер видит `kind: string`, а не `"chest"`, и поле с типом-перечислением не проходит проверку.
Решение — маленькие типизированные конструкторы: `feature("chest", x, z)` в `Rooms.luau`, `add(...)` / `mul(...)` в `Perks.luau`.

**Тип массива берётся по первому элементу** (2026-10-19).
Массив `{ Ui.corner(), Ui.stroke(...) }` получает тип `{ UICorner }`, и следующий элемент «не подходит».
Решение: вспомогательные функции оформления возвращают `Instance`.

**`xpcall` от функции без результата** (2026-10-19).
По типам такой вызов возвращает только `ok`, без текста ошибки.
Решение: сохранять ошибку в обработчике через замыкание (см. `ErrorReporter.try`).

**Свойства в `Ui.new("Frame", { ... })` тип-чекер не проверяет** (2026-10-19).
Таблица свойств имеет тип `any`, поэтому опечатка в имени свойства всплыла бы только в Studio.
Решение — `tools/check_ui_props.py`: скрипт сверяет имена свойств с определениями Roblox API и входит в `tools/check.sh`.

## Порядок запуска и гонки

**Сигнал может сработать прямо внутри `start()`** (2026-10-19).
Если DataStore недоступен, профиль «загружается» мгновенно, и `ProfileLoaded` срабатывает внутри `PlayerDataService.start`. Подписавшийся позже его пропустит.
Правило: подписки делаются в `init()`, работа — в `start()`.

**Быстрый перезаход на тот же сервер** (2026-10-19).
Новая загрузка профиля могла прочитать данные до того, как допишется финальное сохранение прошлой сессии.
Решение: загрузка ждёт, пока завершится выгрузка того же `UserId`. Отдельная защита не даёт загрузить профиль одного игрока дважды.

## Данные

**Точки появления внутри препятствий** (2026-10-19).
Общие точки появления по умолчанию оказались внутри колонн шаблона «Круг колонн».
Ошибку поймал тест `tests/Definitions.spec.luau`, который проверяет каждую точку на пересечение с препятствиями. Новые шаблоны комнат проверяются им автоматически.

## Среда разработки (облачная сессия)

**Релизы GitHub недоступны** (2026-10-19).
Скачать готовые программы с GitHub нельзя. Rojo, StyLua, selene и Lune собраны через `cargo install` с crates.io. luau-lsp собран из исходников через `git clone`.
luau-lsp нужно собирать компилятором clang: GCC падает на ложном предупреждении из-за `-Werror`.

**selene не может скачать API Roblox** (2026-10-19).
Его HTTP-клиент игнорирует прокси и не доверяет его сертификату, поэтому шаг selene в `tools/check.sh` пропускается с пометкой.
Неиспользуемые переменные и подобное ловит luau-lsp: его линтер включён.

## Настройка компьютера (Windows)

**Установщик Claude Code не прописывает путь к программе** (2026-10-20).
После `irm https://claude.ai/install.ps1 | iex` команда `claude` «не распознана». Об этом предупреждает строка `Setup notes` в выводе установщика.
Путь добавляется один раз (команды — в [LOCAL_SETUP.md](LOCAL_SETUP.md)).

**Уже открытое окно PowerShell не видит новый путь** (2026-10-20).
Новый путь работает только в новых окнах. В текущем окне его можно обновить командой `$env:PATH = ...` (см. LOCAL_SETUP.md). Повторный запуск команды добавления пути только дублирует запись.

**PowerShell от администратора не нужен** (2026-10-20).
Строка `PS C:\WINDOWS\system32>` означает окно администратора. Для установки и работы нужно обычное окно: `PS C:\Users\<имя>>`.

## Найдено проверкой в Studio (2026-10-20)

Подробности и замеры — в [reports/phase1-studio-check.md](reports/phase1-studio-check.md).

**Текст ошибки DataStore в `pcall` не такой, как в Output.**
В Output: `DataStoreService: StudioAccessToApisNotAllowed: Cannot write to DataStore from studio if API access is not enabled. …`
В `pcall`: `403: Cannot write to DataStore from studio if API access is not enabled.` — кода `StudioAccessToApisNotAllowed` там нет.
Распознавание вынесено в `Logic/DataStoreErrors.luau` (код `403:` и текст `API access is not enabled`) и проверено тестами на настоящих сообщениях. Раньше сохранение отключалось только через ~10 с повторных попыток.

**Персонаж появляется раньше, чем построен мир.**
При `CharacterAutoLoads = true` персонаж мог появиться до того, как сервер построил Заставу и `SpawnLocation`, — у маяка вместо площадки.
Решение: `CharacterAutoLoads = false` (в `default.project.json` и в коде). `SpawnService` создаёт персонажа после постройки мира и пересоздаёт его после смерти. Уже появившегося до старта скриптов персонажа он тоже пересоздаёт.

**`Player:LoadCharacter` устарел.** Нужно использовать `LoadCharacterAsync` (так сказано в определениях API).

**Интерфейс, уменьшенный под маленький экран, нечитаем.**
Автомасштаб до 0,7 давал на iPhone 7 текст в 9 точек и кнопки в 22 точки.
Решение: при сенсорном вводе (`UserInputService.PreferredInput == Touch`) не уменьшать ниже макета, итоговый масштаб не ниже 0,8, все кнопки не ниже `Theme.TouchTarget` (44 точки). Длинный список в панели прокручивается.

**Кнопка теряет фон после смены выбора.**
Вероятная причина — встроенная подсветка `AutoButtonColor` спорит с цветом, который код меняет программно. У кнопок, цвет которых меняет код, `AutoButtonColor = false`. Невыбранные варианты получили заметный фон и рамку.

**Кириллица в шрифте Builder Sans не подтверждена.**
Интерфейс переведён на Montserrat через `Font.new("rbxasset://fonts/families/Montserrat.json", …)`. Montserrat с кириллицей проверен в прошлом проекте. В `Enum.Font` значения Montserrat нет.

**Скриншоты Studio без 3D-сцены.**
Когда окно Studio свёрнуто или не в фокусе, Studio не рисует 3D и на снимках виден только интерфейс. Перед проверкой внешнего вида окно Studio должно быть на переднем плане.

**`rokit install` без интерактива падает на неподтверждённых инструментах.**
Сначала нужно выполнить `rokit trust <автор/инструмент>`.

**`simulate_keyboard_input` с `tap` и `duration` может вернуть ответ раньше, чем клавиша отпущена** (не перепроверено). После ответа персонаж продолжал идти.

## Найдено независимой проверкой исправлений 1.1 (2026-10-20)

**`AutomaticCanvasSize` ошибается под `UIScale`.**
Если у предка `ScrollingFrame` есть `UIScale` (у нас он у каждого ScreenGui), область прокрутки может посчитаться слишком маленькой, и нижние элементы станут недоступны. Об этом есть несколько сообщений на DevForum, исправления не найдено.
Решение: `AutomaticCanvasSize = None`, а `CanvasSize` задаётся кодом по `UIListLayout.AbsoluteContentSize / масштаб`.

**`UIListLayout.AbsoluteContentSize` уже умножен на `UIScale`, а `ScreenGui.AbsoluteSize` — нет.**
Чтобы получить размеры в единицах макета, их делят на масштаб: `Scale.virtualSize`.

**Окно чата Roblox по умолчанию открывается в левом верхнем углу** (на ПК). Оно рисуется поверх наших ScreenGui.
Левый верхний угол оставлен свободным, валюты перенесены влево, на середину высоты.

**Кнопка прыжка на маленьком экране** занимает 70×70 точек в 95 точках от правого края (PlayerModule, TouchJump). Джойстик слева занимает примерно столько же.
Широкие панели внизу по центру при сенсорном вводе нужно сужать до промежутка между ними.

**Studio с доступом к API пишет в боевое хранилище.**
Тест в Studio записал бы тестовые данные в настоящий профиль и мог бы отобрать блокировку у живого сервера.
Решение: в Studio хранилище с суффиксом `_Studio` (это лучше, чем выключать сохранение целиком: путь сохранения проверяется по-настоящему).

**Принудительный захват блокировки не должен быть быстрее финальной записи.**
Захват через ~10 с мог опередить финальное сохранение прошлого сервера (до 3 попыток с паузами 2 и 4 с). Его последние изменения пропали бы, а запоздалая запись могла затереть новые данные.
Решение: идентификатор сессии в блокировке (писать может только своя сессия, пустая блокировка — тоже потеря), захват не раньше 30 с, запись каждого захвата в лог (`Logic/SessionLock`).

## Работа на компьютере Артёма (Windows, 2026-10-20)

**Git для Windows переводит файлы в CRLF, а `stylua --check` ждёт LF.**
Из-за этого проверка форматирования на Windows падала. Файл `.gitattributes` (`* text=auto eol=lf`) заставляет Git держать LF на всех системах.
Уже скачанные файлы нужно один раз переписать: при чистом `git status` выполнить `git checkout-index --force --all`.

**Claude Code останавливает фоновые команды при нехватке памяти.**
`rojo serve` был остановлен, пока Studio держала несколько окон теста на двух игроках. Лишние окна теста нужно закрывать сразу после проверки, а Rojo — перезапускать. Отключать защиту (`CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP`) не нужно: тогда при нехватке памяти может упасть сама Studio.

**selene завершается с ошибкой даже на одних предупреждениях.**
`tools/check.sh` остановится на selene, если есть хоть одно предупреждение. Предупреждения исправляются, а не подавляются.

**На Windows Python называется `python`, а `python3` бывает заглушкой Microsoft Store.**
`tools/check.sh` выбирает первую команду из `python3` и `python`, которая реально запускает Python 3.

**На Windows Python по умолчанию читает файлы в cp1251.**
Русские комментарии ломали проверку свойств интерфейса. В `tools/check_ui_props.py` кодировка UTF-8 указана явно.

**selene `roblox_manual_fromscale_or_fromoffset`.**
Если у `UDim2.new` нулевые оба отступа или оба коэффициента, пишем `UDim2.fromScale(...)` или `UDim2.fromOffset(...)`.

**StyLua без поддержки Luau молча ничего не проверяет** (найдено благодаря проверке на Windows).
В облачной сессии StyLua был собран из crates.io без `--features luau`. В папках он видел только файлы `.lua`, проверял ноль файлов `.luau` и отвечал «ok». На отдельном файле `.luau` он падал. Из-за этого 14 файлов были не отформатированы, хотя проверка «проходила».
Решение: в `stylua.toml` указано `syntax = "Luau"`. `tools/check.sh` сначала проверяет саму проверку: заведомо неотформатированный фрагмент Luau обязан дать код 1, иначе скрипт останавливается. Собирать StyLua нужно командой `cargo install stylua --features luau`. Официальные сборки (Rokit) уже с поддержкой Luau.
Урок: у каждой автоматической проверки должен быть случай, на котором она обязана упасть.

## Найдено проверкой 1.2 в Studio (2026-10-20)

**Размеры в единицах макета умножаются на масштаб, поэтому «44 точки» не гарантированы.**
`Theme.TouchTarget = 44` задаётся в `UDim2.fromOffset`, а `UIScale` умножает его на множитель. При сенсорном вводе и настройке «Мелкий» (0,85) кнопка превращалась в 37 точек — меньше пальца.
Решение: при сенсорном вводе итоговый множитель не ниже 1 (`MIN_FACTOR_TOUCH`). Настройка «Мелкий» на телефоне теперь ничего не уменьшает: на маленьком экране читаемость и попадание пальцем важнее вкуса.

**В опубликованном месте остаются эффекты освещения из шаблона Roblox.**
Проверка нашла в `Lighting` сразу `Atmosphere`, `Bloom`, `SunRays`, `DepthOfField`, `Sky` рядом с нашими `Goblit*`: два `Atmosphere` и два `Bloom` складывались, и задуманный вид не получался. Rojo их не трогает, потому что `Lighting` не описан в `default.project.json`.
Решение: `HubService` при старте удаляет эффекты перечисленных классов, имя которых не начинается с `Goblit`, и пишет в лог, что убрал. `Sky` не трогаем: своего неба у нас нет.

## Найдено проверкой 1.3 в Studio (2026-10-20)

**В шрифте Montserrat кириллица рисуется с промежутками внутри слов.**
Проверка (R16) показала: дефект только у кириллицы, только в Montserrat, зависит от размера текста (хуже всего 18, на 16, 17, 20, 22 ровно), промежутки стоят посреди строки, а не на переносе. Сам текст чистый: `ContentText` совпадает с `Text` байт в байт, пробелы обычные, `RichText` выключен. На SourceSans промежутков нет, латиница в Montserrat ровная.
Похоже на ошибку округления ширины кириллических букв в движке.
Проверка R19 замерила семь семейств на размерах 11–22: чистые — **Roboto**, **Nunito**, **SourceSans**. С дефектами: Montserrat (почти все начертания), Arimo (пропадает пробел на 13 и 17), Oswald (слишком узкий), RobotoCondensed (мелко на 11–12), Merriweather (с засечками). Интерфейс переведён на Roboto.
Урок: шрифт для русского интерфейса проверяется не только на наличие букв, но и на то, как он выглядит на разных размерах и в разных начертаниях.

**Путь к файлу семейства шрифта не нужно писать строкой.**
`Font.fromEnum(Enum.Font.Roboto).Family` даёт тот же путь, но без риска опечатки в `rbxasset://…`. Дальше начертания строятся через `Font.new(family, вес)`.

**`UserInputService.PreferredInput` до первого касания может показывать мышь.**
В эмуляторе Studio интерфейс оставался «мышиным», пока игрок не коснулся экрана. На настоящем телефоне это не проверено, но полагаться на это нельзя.
Решение: `Scale.isTouch()` считает управление сенсорным, если `PreferredInput == Touch` **или** есть касания и нет клавиатуры.

**Кольцо джойстика уходит внутрь экрана дальше, чем кнопка прыжка.**
Измерено: до кнопки прыжка от края 95 точек, до края джойстика — 103. Панель внизу по центру нужно сужать по дальней границе, иначе с одной стороны зазор нулевой.

## Найдено проверкой шрифта (2026-10-20)

**В семействе Roboto нет начертания ExtraBold, и движок молча рисует Bold.**
Замер (R20): доля закрашенных пикселей у Bold и ExtraBold одинаковая — 0,292, ширина строки тоже совпадает. То есть заголовки не отличались от кнопок по жирности, а ошибок в Output при этом нет.
Решение: `Theme.Fonts.Heavy` использует `Enum.FontWeight.Heavy` (900). Если и его нет, движок снова подставит Bold — хуже не станет. Урок: отсутствие начертания нигде не видно, его нужно замерять.

**Постоянный текст HUD перекрывает надписи в мире.**
Название зоны «Застава» висело ровно поверх надписи GOBLIT на арке.
Решение: название зоны показывается при входе в зону и через 4 секунды исчезает. Постоянно висеть ему незачем.

**Надпись в мире видна гораздо хуже на телефоне.**
Буквы GOBLIT на арке с места появления занимали на iPhone 7 около 6 пикселей в высоту при нормальном размере на ПК. Надписи в 3D рассчитываются по расстоянию: размер на экране зависит от высоты окна в пикселях.

**Размер букв в мире упирается в потолок размера шрифта.**
Размер шрифта в Roblox не бывает больше 100, поэтому `TextScaled` на `SurfaceGui` перестаёт расти, и высота букв в мире равна `100 / PixelsPerStud` стадов. При 40 это 2,5 стада, и увеличение самой детали добавляло вокруг букв только пустое поле: текст занимал 301 пиксель из 1120 (проверка R25). Чтобы буквы выросли, нужно уменьшать `PixelsPerStud`, а не увеличивать деталь.
Урок: если текст «не растёт», сначала проверьте, не упёрся ли он в предел, а не увеличивайте то, что его содержит.

**Пункт Studio называется Experience Settings, а не Game Settings.**
Доступ к DataStore включается в *File → Experience Settings → Security → Enable Studio Access to API Services → Save*. На ленте Home этой кнопки нет.

## Найдено проверкой фазы 2а (2026-10-21)

**`BillboardGui` не попадает в снимки через `robloxstudio-mcp`.**
Полоски здоровья врагов и цифры урона на снимках отсутствуют, хотя в игре видны. Проверено так: клиентская `Part` в той же точке на снимке есть, `BillboardGui` с непрозрачным фоном — нет; `SurfaceGui` (надпись на арке) снимается нормально. Виден и `ScreenGui` (HUD). Снимок делается через `CaptureService` (в ответе `studioFastPathUnavailable`), `target: "window"` не помогает.
Урок: содержимое `BillboardGui` проверяйте чтением свойств (`Enabled`, `Text`, `TextSize`, `TextColor3`, `AbsoluteSize`), а не глазами по снимку.

**Фокус окна Studio для снимков нужно удерживать, а не выставлять один раз.**
`SetForegroundWindow` из PowerShell часто не срабатывает с первого раза (Windows не отдаёт фокус процессу не из переднего плана), а между возвратом команды и снимком фокус успевает уйти. Работает цикл, который раз в ~0,1 с возвращает фокус всё время, пока делается снимок.

**`ShowWindow(h, SW_RESTORE)` разворачивает максимизированное окно Studio.**
Вьюпорт уменьшился с 1640×753 до 678×264, и снимки стали другого размера. Вызывать `ShowWindow` только если окно свёрнуто (`IsIconic`).

**`simulate_mouse_input` доходит до игры через раз.**
Клик срабатывал, когда прямо перед ним выполнялся `eval_client_runtime`, и терялся после `capture_screenshot` или возни с фокусом из PowerShell. Рабочий порядок: `eval_client_runtime` → клик → `eval_client_runtime` для проверки результата.

**В эмуляции телефона координаты клика — это координаты игрового экрана, а не пиксели снимка.**
На iPhone 7 игровой экран 666×374, а снимок 1109×623. Клик по координатам, снятым со снимка, не доходит никуда.

**`ContextActionService:GetButton()` подвешивает `eval_client_runtime`.**
Запрос падает по таймауту, выполнение при этом не отменяется.

**`game:GetService("CoreGui")` в `eval_client_runtime` возвращает `nil`.**
Читать CoreGui можно через `execute_luau` с `target: "client-1"`.

**Экранная кнопка от `ContextActionService` лежит в `PlayerGui`, а не в CoreGui.**
Путь: `PlayerGui.ContextActionGui.ContextButtonFrame.ContextActionButton`, подпись — в `ActionTitle`.

**`ContextActionService:SetPosition` не знает про стандартные кнопки управления.**
`UDim2.new(1, -150, 1, -140)` на iPhone 7 положило кнопку «Удар» (45×45) целиком внутрь кнопки прыжка (70×70). У прыжка `ZIndex` 10 против 1, поэтому нажатие уходило ему, и ударить с телефона было нельзя. Положение экранных кнопок нужно сверять с `PlayerGui.TouchGui.TouchControlFrame`: `JumpButton` и `DynamicThumbstickFrame`.

**`NetServer` пишет об отклонении не чаще раза в 30 с на игрока.**
`VIOLATION_LOG_INTERVAL` = 30. Если в плане проверки две защиты идут подряд, сообщения от второй в Output не будет, хотя запрос отклонён. Между такими пунктами нужна пауза больше 30 с.

**Запас на сетевую задержку в проверке перезарядки выдаётся на каждый удар.**
`sinceLast < interval - TimingTolerance` означает, что сервер принимает удары каждые 0,22 с вместо 0,42 с. Клиент, который шлёт `Attack` напрямую, получает 3,6 удара в секунду вместо 2,38 — в полтора раза больше урона. Запас, выдаваемый каждый раз, это не компенсация джиттера, а постоянная скидка.

Лечится не уменьшением запаса, а сменой точки отсчёта: хранить не «когда был прошлый удар», а абсолютный срок следующего и считать новый срок от срока, а не от момента удара (`readyAt := max(now, readyAt) + interval`, см. `src/shared/Logic/AttackClock.luau`). Тогда опережение не копится — средний темп остаётся 1/interval при любом спаме, — а простой не запасается впрок. Это общее правило для любой перезарядки с допуском: способности, рывок, зелья.

**Своя экранная кнопка должна знать, где стоят штатные.**
Место и размер кнопки прыжка зависят от размера экрана (`PlayerModule` делает её крупнее на больших экранах), поэтому жёсткие отступы рано или поздно наложатся на неё. Надёжнее читать `AbsolutePosition`/`AbsoluteSize` у `PlayerGui.TouchGui` → `JumpButton` и ставить свою кнопку относительно неё, оставив измеренное значение запасным вариантом. Расстояния при этом переводятся из пикселей в единицы макета делением на `Scale.factor()`, иначе при масштабе интерфейса кнопка уезжает.

## Найдено повторной проверкой фазы 2а (2026-10-24)

Подробности — в [reports/phase2a-studio-check.md](reports/phase2a-studio-check.md), раздел «Повторная проверка».

**Срок следующего удара нельзя ставить по ответу сервера.**
Клиент считал `время_прихода_ответа + остаток_перезарядки`. Остаток сервер считает в момент приёма запроса, поэтому к каждому удару добавлялось время пути пакета туда и обратно: в Studio шаг удержания был 0,48–0,50 с вместо 0,42, а с пингом 200 мс было бы ~0,6 с. Скрипт, который спамит запросы, при этом бил быстрее честного игрока.
Правило: клиент держит ровный шаг сам (`AttackClock.nextRequest`, отсчёт от прошлого срока), а опоздания пакетов покрывает запас на сервере. Касается любой перезарядки: рывок, способности, зелья.

**Отпускание «своей» кнопки на телефоне сверяется с тем же касанием.**
Если останавливать удержание по любому `InputEnded` типа `Touch`, его прерывает палец, снятый с джойстика или с камеры. `InputObject` касания один на всё время жизни пальца: запомните его в `InputBegan` кнопки и сравнивайте в глобальном `InputEnded`.

**Лимит частоты события должен быть выше самой быстрой честной частоты.**
Лимит `Attack` 4/с был ниже 4,76/с, которые даёт потолок `AttackSpeed = 2`. Такие пары чисел из разных файлов сверяются тестом (см. `tests/AttackClock.spec.luau`, «лимит частоты Attack»).

**Свёрнутое окно Studio даёт пустые снимки, хотя считается активным.**
`GetForegroundWindow` возвращал окно Studio, а 3D на снимке было пустым: окно было свёрнуто (`GetWindowRect` = −32000; −32000). Цикл фокуса должен каждый раз проверять `IsIconic` и разворачивать окно на весь экран (`ShowWindow(h, 3)`, а не `SW_RESTORE`: тот уменьшает максимизированное окно, см. выше).

**Claude Desktop не отдаёт фокус на обычный `SetForegroundWindow`.**
Помогает отпущенное нажатие Alt через `keybd_event(0x12, …)` прямо перед вызовом: тогда Windows разрешает сменить окно на переднем плане.

**В эмуляции телефона протяжку и второй палец через инструменты не проверить.**
`simulate_mouse_input` с `move` отклоняется («у клиента нет мыши»), нажатие и отпускание работают и приходят в игру как `Touch`. `VirtualInputManager:SendTouchEvent` недоступен даже из `execute_luau` (нужна способность `RobloxScript`). Такие пункты плана помечаются «только настоящий телефон».

**Замороженный модуль нельзя подменить для наблюдения.**
`NetServer` возвращается через `table.freeze`, поэтому обернуть его функцию в работающем тесте нельзя. Наблюдать приходится снаружи: по Output, по событиям и атрибутам.
